1. **DOM lookups: per-feature or one table.** `core/dom.js` eagerly resolves 525 ids (two eras inside the file: 177 via `byId`, 322 via `doc.getElementById`); `main.js:160-682` destructures ~520 of them, and 76 raw `document.getElementById` calls remain for ids not in the table. (a) Move each feature's lookups next to the feature so the table shrinks to shared shell elements; enables the module split. (b) Commit to the table and move the 76 inline lookups in. Recommendation: (a). → `A_long-main-js-module-split__20260924.md`.
   - Decision (2026-10-03): owner approved per-feature lookups; implementation is active in the module-split ticket.
2. **Load order: defer scripts and make random-events CSS non-blocking.** Home loads 369 KB of render-blocking CSS across 13 stylesheets (`random-events.css` 160 KB for 45 windows that are `display:none` at load) and 1,047 KB of blocking `main.js` with no `defer`. Options: `defer` the script chain (order preserved), load `random-events.css` and per-app CSS via `rel=preload as=style onload` or inject per event on trigger, preload the 6.5 KB `ms_sans_serif.woff2`. Cost: visual baselines shift and prerender/activation timing (`window.rohinHomePerf`) changes; LCP was not measured in a browser. Recommendation: measure first with the `web-perf` skill, then defer scripts. → `O_long-random-event-boilerplate__20260924.md` and small.
3. **Dialog ARIA pattern.** Of 240 `.window` containers, 14 have `role=dialog|alertdialog` (12 with `aria-modal`), 103 hidden windows have no role, 75 of those only `aria-hidden`, none `aria-labelledby`; `main.js` toggles `aria-hidden` in 237 places. Options: native `<dialog>` (one exists: `sudoku-errors-prompt`, `home.html:2275`) or `role=dialog` + `aria-modal` + `aria-labelledby` = title-bar text id, applied through the shared open/close helper. Recommendation: `role=dialog` + `aria-labelledby` via the managed helper (native `<dialog>` changes stacking and focus behaviour for 240 windows). → long after the boilerplate ticket.
4. **Lazy-load Admin Controls.** `home.html:6861` loads `admin-controls.js` (68 KB) and `admin-controls.css` (17 KB) for every visitor; `create()` (`admin-controls.js:251-258`) never bails because `#admin-controls-window` is always present, so every visitor gets a body-wide subtree `MutationObserver` and a global `HTMLMediaElement.prototype.play` patch. `tests/admin-controls.test.mjs:150-162` asserts the literal script tag and its order after `main.js`; `O_admin-controls__20260731.md` still awaits manual acceptance of the current flow. Options: inject the script when `hasActiveGameStatsAdministratorProof()` becomes true (from the launcher at `main.js:18324`) and update the test, or keep the static tag and only defer the observer/patch to first open. Recommendation: complete the pending manual acceptance first, then lazy-load. → `O_long-shared-cross-route-modules__20260924.md`.
5. **`neko-stream-system-alert` is registered with `debug: true` in production** (`main.js:17166`); its `canTrigger` restricts it to the Start-button trigger and `tests/random-event-debug-fixture.test.mjs:27` requires the flag to stay. A "debug" flag that is load-bearing will be "fixed" by a future author. Rename the field (e.g. `startButtonOnly: true`) and update the fixture test, or document why. Recommendation: rename. → small.
