## Items

1. **Session budget: 24 sessions per IP-hash per hour.** Every game start requests a Worker session (`main.js:29138-29147` Minesweeper first click, `:8212-8227` Snake, `:19352-19362` Sudoku, `:29676-29679` Solitaire) and the Worker throws 429 on the 25th within `RATE_LIMIT_WINDOW_MS` = 1 h (`workers/game-stats/src/index.mjs:53-54, 1010-1031, 1187`). Snake and beginner Minesweeper games last seconds; a loss plus reset is a new session. Wins in the rest of that hour are saved locally but never published, and the rejected request still counts. The budget is not stated in `docs/validation/game-stats-backend.md`. Options: (a) reuse an unconsumed, unexpired session for the same game and config across losses and resets (must respect whatever session-age vs metric checks the Worker applies); (b) raise the budget; (c) both. Recommendation: (c). → `O_long-shared-game-layer__20260924.md` and the Worker constant.
2. **Minesweeper timer semantics.** It is an incrementing `setInterval` (`:29142-29147`) with no `visibilitychange` handler, so a background tab undercounts the leaderboard metric; Snake pauses on hidden/blur, Sudoku pauses on close. Options: wall-clock like Sudoku (`startedAt` + `Date.now()`, cap 999) or explicit pause on hidden/blur like Snake. Recommendation: wall-clock (matches what a leaderboard time means). → small.
3. **Closing Minesweeper discards the game; other games pause.** `closeAppWindow("minesweeper")` calls `msNewGame` (`:18869-18871`); Snake and Sudoku pause. Options: keep reset, or pause for consistency. Recommendation: pause. → small.
4. **Snake's rAF loop keeps running on the game-over screen** while visible and focused (`:8027-8032`, `:8050-8052`), bounded by blur/hidden/close. Likely intentional for the static-noise effect. Confirm intent; if not intended, stop after the last collection pulse. → small.
5. **Sync queue retry.** After a transient failure the queue (max 100, oldest dropped silently at `:1713`, `:2785-2787`) drains only on load, `online`, Game Progress open, or the next record. Options: leave as is; add one backoff retry; show a dropped count. Recommendation: one backoff retry plus a visible count. → small.
6. **Expired sessions at completion.** Worker `SESSION_TTL_MS` is 6 h; a game left open longer publishes nothing ("could not pass server verification"). Requesting a fresh session at completion only works if the Worker accepts a session younger than the metric; confirm the Worker's session-age check policy. → `O_long-shared-game-layer__20260924.md` item 6.
7. **`GAME_BUILD_COMPATIBILITY_VERSIONS` sits at its hard cap of 32.** `wrangler.jsonc` has exactly 32 entries; the Worker 500s above 32 (`src/index.mjs:847`), the updater slices to 32 (`update-game-integrity.mjs:93`), so the oldest hash silently drops each release. At the 2026-09-24 cadence (4 pushes/day) the grace window for cached browsers is days. Decide the intended window (time-based expiry or a documented N) and note it in `game-stats-backend.md`. → small.
8. **Committed `database_id`** in `wrangler.jsonc:13` while the `.example` uses a placeholder. Keep in git or move to an env/secret. Recommendation: keep (it is not a credential) and say so in the doc. → `O_small-ci-and-worker-fixes__20260924.md`.
9. **Drop the six unused D1 indexes?** They are used by no query today (`migrations/0001:18-23`) but the SQL aggregation in `O_long-worker-stats-aggregation__20260924.md` may want some. Recommendation: decide together with that ticket's new queries; one migration.
10. **Deploy gating on the browser suite.** The Worker and Pages deploy on `verify` alone; a push that breaks `home.html` deploys while Browser UI is still running or failing (happened at eccfd37: release succeeded 21:37, UI failed 22:19). Options: make the UI job a `needs` of `deploy-worker` (adds ~20 min to every release until the suite is sharded), or `workflow_run` gating, or accept the risk. Recommendation: gate after sharding lands. → `O_long-test-suite-hardening__20260924.md`.
