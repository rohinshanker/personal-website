# Sudoku Board Controls

- Purpose: Preserve the keypad, highlight, and keyboard contract for the Sudoku board.
- Scope: Off-thread puzzle generation, pause, keypad exhaustion, same-value highlighting, the N notes shortcut with its hover hint, window-level digit entry, the full-board Check prompt, and rendered browser validation.
- Last verified: 2026-09-28

## Contract

- A digit with nine placements on the board is exhausted: its keypad button gains `is-exhausted`, is disabled, and renders greyed. Placements count givens and entries alike, so a wrong ninth entry still exhausts the digit. Keyboard entry stays open so that entry can be overwritten; clearing any placement re-enables the button.
- Each digit button also reports its remaining placements in a corner badge, so the keypad shows the whole count rather than only the greyed state at nine. The badge opens on the puzzle's givens and follows every placement, clear, undo, redo, and new puzzle. At zero it empties, because the greyed button already says so. It is `aria-hidden`; the button carries the same fact in its accessible name, `<digit>, <n> left` or `<digit>, none left`, which keeps the visible digit at the front of the label. Erase and Notes carry no badge.
- Selecting a cell with a value adds `is-same-value` to every other cell holding that value. The selected cell keeps only `is-selected`; row and column cells keep `is-axis-highlight`. The value tint is the `--sudoku-value-highlight` layer, present on plain and given cells, and it refreshes after every value change, undo, redo, and selection.
- A written pencil mark naming the selected value lights up in the same blue as the value tint. Each note slot always stands for the same digit and carries `data-sudoku-note`, and the grid carries the selected value as `data-sudoku-note-highlight`, so the stylesheet pairs them and the whole board follows one attribute. Empty slots are excluded by `:not(:empty)`: an unwritten slot is not a pencil mark. Selecting an empty cell drops the attribute and the highlight with it.
- Placing a digit clears that digit's notes from the placed cell's row, column, and box; `SUDOKU_PEER_INDEXES` holds those twenty peers per cell. There is no toggle, because the clearing is part of the move: the undo entry is taken before the placement, so one undo restores the value and every note it retired, and one redo replays both. Notes mode writes a pencil mark rather than a value, so it retires nothing; erasing a value does not bring retired notes back on its own.
- `N` toggles notes while the visible Sudoku window is the active window and the game is playing. It is ignored during the Errors prompt, with Control, Meta, or Alt held, while repeating, and inside text inputs. The Notes button exposes `aria-keyshortcuts="N"` and is described by the hint.
- Hovering the Notes button shows `Press N to toggle` in the Solitaire pile-hint style: black, white text, no transition, `position: fixed`, twelve pixels below and right of the pointer, pulled back four pixels from the viewport edge, hidden on pointer leave. The hint is a body-level `#sudoku-note-tooltip` with `role="tooltip"` so window transforms cannot displace it, and it ignores touch pointers.
- A board holding 81 values that is not yet solved can only be resolved by Check, so `#sudoku-check` gains `is-board-full`: a gold `--sudoku-prompt-gold` ring and halo plus the Windows 98 sunken-then-raised press played twice. The glow outlasts the press and holds until a cell is cleared, the puzzle is solved, or a new puzzle starts; refilling the board replays the press. `prefers-reduced-motion: reduce` keeps the glow and drops the press. The prompt is visual only and must not move focus or change the status text, the keypad, the check count, or the assistance latch.
- The prompt rides `updateSudokuBoardHighlights` and one module-level flag, so it adds no board scan of its own and a later update cannot restart the press mid-glow. `checkSudokuBoard` refreshes it once more because solving does not otherwise re-enter that path.
- Both refreshes run on every keystroke, so each diffs against the class state it last wrote and skips a cell or button whose state is unchanged; a refresh that changes nothing touches no element. The caches are keyed on the element list itself, so the fresh cell array `renderSudoku` builds retires the previous states without a separate invalidation step. Nothing outside `updateSudokuBoardHighlights` may write `is-selected`, `is-axis-highlight`, or `is-same-value` on a cell, and nothing outside `updateSudokuNumberButtons` may write `is-exhausted` or `is-selected` on a keypad button, or the diff goes stale.
- Digits, `0`, Backspace, and Delete edit the selected editable cell whenever the active Sudoku window is playing, even while a keypad, difficulty, hint, or action button holds focus. Notes mode is honoured. Events the grid already handled, modifier chords, text inputs, and given cells are left alone.
- While the solved dialog or the Errors prompt is open, every Sudoku key path is inert: the window-level handler, the grid's own keydown (digits, `0`, Backspace, Delete, and arrow navigation), and the undo/redo shortcut all consult one `isSudokuModalOpen` guard. The solved dialog is an overlay, not a native modal, so a cell underneath can still take focus; the guard is what keeps a keypress there from editing or rewinding a finished board. Dismissing the dialog restores every path.

## Generation Contract

- Puzzles are carved in `scripts/home/sudoku-generator.worker.js`, which owns generation outright: `main.js` keeps no carve of its own. Carving re-solves the grid after every removed clue, and on the main thread that ran once during script evaluation and again on every New Game, freezing the window both times.
- The worker's URL is declared once, as the `#sudoku-generator-source` prefetch link in `home.html` with `as="worker"` and a `?v=` cache token, and `main.js` reads it from there. The token is mirrored in the `index.html` warm-up list, and the file is listed in `tests/asset-references.test.mjs`. The prefetch downloads the file; it does not run it.
- The worker is a game-completion source, so its token is the generated build token rather than a hand-written date: the solution it returns becomes `sudokuState.solution`, which is what decides whether a board is correct and complete. It is listed in `GAME_COMPLETION_SOURCE_FILES` and `INTEGRITY_CACHE_ASSET_PATHS`, so `node scripts/update-game-integrity.mjs` writes that token into both entry points, and a release that changes only the worker changes the build version. Never edit the token by hand.
- Protocol: post `{ requestId, difficulty, targetClues, maxAttempts }`, receive `{ requestId, difficulty, puzzle, solution, clues }` or `{ requestId, difficulty, error }`. The worker never mints a puzzle id. `main.js` assigns one at the moment a puzzle is adopted, so identity belongs to the state that saves it and never to the pool.
- Before the first puzzle is adopted the board is blank scaffolding — an all-zero puzzle, no id — and the site generates nothing. Opening Sudoku is what starts the generator, so a visitor who never opens it never pays for a puzzle.
- One spare is kept warm per difficulty in play (`SUDOKU_POOL_TARGET`), refilled in the background after each use. Untouched difficulties are never pre-generated. A warm New Game swaps the board in the same tick; a cold difficulty returns immediately and adopts the puzzle when the worker delivers, with the grid `aria-busy` until then.
- The boot loader holds at 98 percent until a real puzzle exists and offers Play on readiness, never on a timer alone. The newest request wins, so a superseded generation cannot land on the board.
- Only one request can reach the board, so a superseded one is withdrawn from the waiting list rather than left to draw a generation nobody will adopt: ten impatient clicks on a cold difficulty are one board's worth of demand, not ten, and each extra click adds no work. Generation already in flight still delivers, and `returnSudokuPuzzleToPool` caps what it keeps at `SUDOKU_POOL_TARGET`, so a settled burst leaves exactly one warm spare and no running request.
- When the worker cannot start or dies, every pending and future request resolves with the static puzzle the site already ships for that difficulty. Generation never moves back to the main thread.
- Unavailable generation is answered where the request is made, in the same tick, and never by queueing a waiter: the pool stops refilling once the worker is gone, so a queued request would wait forever. That is why a cold difficulty chosen after the failure swaps the board immediately instead of holding the previous puzzle behind a `Generating` status, and why New Game keeps working past the last pooled spare.

## Pause Contract

- `#sudoku-pause` in the actions row pauses a playing, unsolved board; `#sudoku-resume`, the single play button centred on the board, is the only way back. Pause carries `aria-pressed`, and the status line reads `Paused` and returns to whatever it said before.
- Pausing stops the clock through `pauseSudokuTimer`, so the elapsed time holds while paused and resumes from where it stopped. It does not stop the window: `sudokuState.playing` stays true, so the aquarium keeps swimming behind the paused board.
- While paused every value and note is `visibility: hidden` — hidden, not faded — and the grid frame and control panel drop to a thin wash so the aquarium reads through them. Both regions also carry `inert`, so the paused board cannot be clicked, tabbed into, or typed on, and `isSudokuBoardLocked` extends the modal guard over the grid keydown path, the window-level digit path, and the undo/redo shortcut. The CSS is the look of the lock; `inert` and that guard are the lock.
- The overlay and the grid frame share one `.sudoku-board-stack` box sized to the frame, because at 375 px the frame is wider than its column; anchoring the overlay to the column would put the button off the board's centre.
- Pausing moves focus to the resume button, and resuming returns it to the selected cell. Focus never lands inside an inert region.
- A hidden tab pauses the game as well as the aquarium. Returning to the tab does not resume it, so time never runs on a board nobody is looking at.
- A puzzle can be adopted while the board is paused, because a cold difficulty generates in the background and the tab can hide meanwhile. Adoption keeps the pause: the status stays `Paused`, the board stays hidden and inert, and the reset clock does not start. The status kept for the resume is replaced with the new puzzle's own `Ready`, because the one the old board carried in no longer describes what is on screen.
- Pause is module state, not puzzle state: it is absent from the save payload and cleared whenever the boot sequence starts or the window closes, so a reopened Sudoku comes back through the loader and its Play button.

## Verification

Run:

```bash
node --test tests/sudoku-check-eligibility.test.mjs tests/sudoku-completion-recording.test.mjs \
  tests/asset-references.test.mjs tests/entry-point-cache-tokens.test.mjs
node scripts/update-game-integrity.mjs --check
npx playwright test tests/ui/sudoku-board-controls.spec.mjs tests/ui/sudoku-check-controls.spec.mjs \
  tests/ui/sudoku-notes.spec.mjs tests/ui/sudoku-keypad-counts.spec.mjs \
  tests/ui/sudoku-generation.spec.mjs tests/ui/sudoku-pause.spec.mjs \
  tests/ui/sudoku-desktop-layout.spec.mjs tests/ui/accessibility.spec.mjs
```

The spec renders 375×812, 768×1024, 1280×800, and 1440×900 with an exhausted digit and its highlighted placements, then verifies the greyed keypad color and opacity, the tint on exactly the eight matching cells, no document overflow, the hint's computed style and pointer tracking, typed entry from focused panel buttons, and that keys pressed on the solved dialog leave the board, notes mode, and status unchanged. The check-controls spec renders 375×812 and 1440×900 with a full unsolved board and samples the paused press animation to confirm the sunken frame, the raised frame, and that the gold glow survives both. The notes spec renders the same four viewports with pencil marks seeded across a row, a column, a box, and an unrelated cell: it checks that only written slots light up, that the count matches the seeded marks exactly, and that a placement retires the digit from its peers and no further, through undo and redo. The keypad-counts spec renders the same four viewports, checks every badge against the board's own placement counts, requires each badge to stay inside its button with the digit still visible, and walks one digit down to exhaustion and back through a clear, an undo, and a new puzzle. The generation spec drives a real worker: it checks the versioned prefetch declaration, that a page which never opens Sudoku carves nothing, that Play is offered on a real carved puzzle with one spare warm for that difficulty alone, that New Game and a cold difficulty each return in under 50 ms, and that a browser whose `Worker` constructor throws still gets the shipped static board. A burst case delays the worker's replies and fires ten clicks at a cold difficulty, then checks that one waiter and at most two generations exist while they are outstanding and that the settled pool holds exactly one spare with nothing left running. A second failure case covers what comes after that first board: a cold difficulty, three New Games past the last spare, and a further difficulty change each swap the board at once, leave no waiter or request outstanding, and end on a playable grid reporting `Ready`. The pause spec renders all four review viewports with a value and a pencil mark on the board: it checks that no value or note stays visible, that the frame and panel fall below 0.3 opacity and both go inert, that exactly one resume button sits within a pixel of the board's centre, and that resuming restores all of it. It also drives the pinned clock across a pause to prove the timer holds, forces a click and a digit and an undo at a paused board, simulates a hidden tab, and reopens a closed paused window on the loader. Two further cases delay the worker's replies so a cold difficulty is still outstanding when the pause lands, by hand and by hiding the tab, and check that the arriving puzzle leaves the pause, the hidden board, and the stopped clock exactly as they were, and that resuming reports the new puzzle's `Ready`. Screenshots land under `test-results/` as `sudoku-board-controls-<w>x<h>.png`, `sudoku-check-prompt-<w>x<h>.png`, `sudoku-note-highlight-<w>x<h>.png`, `sudoku-keypad-counts-<w>x<h>.png`, `sudoku-paused-<w>x<h>.png`, and `sudoku-note-hint-1280x800.png`. Changing `styles/home/apps/sudoku.css` requires a new cache token in both HTML entry points and the eligibility test.

## Compact layout

At the compact breakpoint, the board frame and control panel share one centered
track inside the aquarium. Grid cells shrink to account for frame padding and
both borders; the board must not overflow its frame. The keypad and the right
control column align at their top and bottom, with spare height assigned to
keypad buttons rather than the Numbers label.

`tests/ui/sudoku-desktop-layout.spec.mjs` checks these bounds at 375px and 680px
and the side-by-side layout immediately above the breakpoint at 681px.

In the wider layout, action rows are New Game/Pause and Redo/Undo, with
equal-width buttons spanning the same bounds as Hints. Check is centered on
a third row. DOM order follows the visual sequence for keyboard navigation.
